# 开源贡献面经案例

本文件只保存公开页面中明确出现的开源经历或开源项目追问，用来帮助 `/contributor` 解释追问路径。它不是企业面试题库，也不代表某家公司固定的面试流程。原帖没有写出的内容必须标为“原帖未记录”，不能根据录用结果或岗位名称补推。

## 公开案例

### B 站微服务开发一面挂经

- 来源：[牛客：B站微服务开发-一面挂经](https://m.nowcoder.com/discuss/570096504870805504)
- 原帖明确记录：候选人介绍了开源贡献；面试官问“开源贡献的项目是解决什么问题的”。原帖还记录了 Kubernetes、etcd、HTTP/QUIC、Redis 和生产者消费者模型等其他技术问题。
- 原帖未记录：候选人的具体回答、代码行、PR review 过程和贡献是否影响面试结果。
- 用法：示范面试官会先问贡献解决的问题，再决定是否进入技术细节。

### 24 届数据库存储岗面经

- 来源：[牛客：24届数据库存储岗面经](https://m.nowcoder.com/discuss/565331793847558144)
- 原帖明确记录：候选人参加 OB 比赛期间给官方 MiniOB 修了两个 bug、提了两个 PR；面经还列出 MiniOB 架构、MVCC 更新、磁盘数据修改和索引联动等深挖问题。
- 原帖未记录：每个问题是否直接由某一个 PR 引出、候选人的完整回答和 PR 是否合并。
- 用法：示范贡献事实会和项目架构、数据一致性及具体实现一起被追问。

### Galxe 一面

- 来源：[牛客：Galxe - 一面](https://m.nowcoder.com/discuss/721795773402218496)
- 原帖明确记录：面试官让候选人在参与的开源项目和个人项目之间选择一个重点介绍。
- 原帖未记录：开源项目具体改动、PR 链接、后续技术问题和候选人的回答。
- 用法：示范面试官会先验证候选人能否选择并完整讲清一段真实经历。

### Galxe 二面

- 来源：[牛客：Galxe - 二面](https://m.nowcoder.com/discuss/722502110004195328)
- 原帖明确记录：面试官追问候选人参与的开源项目中使用的 RocksDB，并询问对 RocksDB 的了解；原帖标注该轮已拿到 offer。
- 原帖未记录：RocksDB 问题是否由某个具体改动引出、候选人的完整回答和开源贡献对结果的单独影响。
- 用法：示范技术组件会成为开源项目经历的深入追问入口，但不能把该组件问题套到没有相关事实的贡献上。

### 腾讯 IEG 后端开发实习面经

- 来源：[牛客：腾讯 IEG 后端开发实习面经](https://m.nowcoder.com/discuss/856524379595812864)
- 原帖明确记录：面试官打开项目 GitHub 对照源码提问，并表示会继续查看候选人的 GitHub；原帖提到候选人的开源贡献较多。
- 原帖未记录：具体源码问题、贡献内容、PR 状态和 GitHub 经历对结果的影响。
- 用法：示范公开仓库链接可能成为面试官核对源码的入口，但不能据此编造具体追问。

### 小米云原生秋招补录面经

### 美团到店前端日常实习面经

- 来源：[牛客：美团到店前端日常实习面经](https://m.nowcoder.com/discuss/576793891735683072)

## 使用规则

生成第三部分时：

1. 先选与本次事实最接近的案例，并说明相似点和差异；没有直接对应案例时写明没有找到，不强行匹配。
2. 将公开案例问题标成“原帖明确记录”，将结合用户事实生成的问题标成“基于本次事实生成”。
3. 对每个生成问题绑定 Issue、根因、改动、验证、PR 或组件证据；缺证据就放到“事实缺口”，不要生成第一人称回答。
4. 不把“面试官看了 GitHub”“PR 被提到”解释为合并、采用、加分或录用原因，除非来源原文明确这样说。
